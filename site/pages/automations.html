04 · Automations

The day,
stored onboard.

Oasis’s Light Cycle is not merely a sequence replayed by the phone. It is represented as ordinary room automations and sent to the device as a complete schedule.

Fixed timeSunrise + sunset20 entries per room

A schedule is a room program.

Each automation names a target state and when to reach it. Entries can be fixed-time or solar-relative, repeat on selected weekdays, and fade brightness and temperature over time.

{
  "id": "…",
  "name": "…",
  "enabled": true,
  "brightness": 72,
  "temperature": 3000,
  "fadeDuration": 1800,
  "daysOfWeek": [1, 2, 3, 4, 5],
  "startTime": { "type": "sunset", "offset": -30 },
  "roomIDs": ["…"]
}

The public guide intentionally omits private schedule IDs, exact household times, and location data.

Light Cycle

A friendly name for the same machinery.

The client’s migration code shows older Light Cycle configuration becoming ordinary automations. That is valuable: compatibility does not require inventing a competing scheduler. It requires faithfully reading and round-tripping the schedule model Oasis already uses.

Why editing is still gated

A partial or stale schedule write could replace entries created in the official app. Public editing should wait until the bridge can read current state, preserve unknown fields, write the entire room set, and verify the result.

What the Mac app can safely add first

  • Read-only visualization of the recovered daily curve.
  • Previewing the brightness and temperature expected at a selected time.
  • Conflict warnings when the official app changes schedule state.
  • Export and diff tools before any write is allowed.
