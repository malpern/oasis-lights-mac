06 · Home Assistant

Local control,
without Matter.

Matter was the first hypothesis. The validated Ambient 2 units advertise no enabled Matter capability, so the practical integration is a small local bridge that speaks Oasis on one side and stable lighting semantics on the other.

Local bridgeTwo light entitiesNo resetEarly alpha

Why the Matter path stopped.

The Oasis clients contain Matter-related software paths, but product capability data for the validated devices says is_matter=false. The installed Home Assistant Matter server had zero nodes because there was no discoverable Matter accessory to commission—not because Home Assistant itself was missing the integration.

The useful finding

Working local control was achieved without opening a commissioning window, extracting setup codes, or changing pairing state. That is a better compatibility boundary for these particular lights.

Reliability model

Command success is not state truth.

The official client uses optimistic updates and later cloud reconciliation. The bridge can reliably report whether it accepted and transmitted a command, but ordinary incoming status is not yet fully decoded. Home Assistant entities must distinguish “last commanded” from “confirmed current.”

The safe progression

  1. Expose one entity per physical light plus an optional room group.
  2. Validate repeatable power and brightness from Home Assistant.
  3. Add white temperature and RGB with clear capability reporting.
  4. Decode incoming state before claiming fully authoritative entity state.
  5. Keep automation schedule editing separate until complete round-trip safety exists.
Project status

The adapter is an early alpha integration, not an official Oasis or Home Assistant component. The local protocol library and bridge are the stable foundation; entity polish and state reconciliation remain active work.
