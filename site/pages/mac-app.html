05 · Mac App

Visible when called.
Quiet otherwise.

The architecture separates the native controller you launch from the bridge that stays available. The bridge belongs to the app, launches automatically on its host Mac, and has no Dock or app-switcher presence.

SwiftUIHeadless bridgeKeyboard shortcutsSparkle updates

Two roles, one product.

A controller and a service have different lifecycle needs. The visible app should feel like an app. The Bluetooth owner should feel like infrastructure.

The bridge is installed and removed through the controller’s settings, so there is one user-facing management surface. On a multi-Mac home, only the Bluetooth host needs the bridge; every trusted Mac can run the controller.

Control surface

Daily controls stay direct.

Power

Control one light or the whole room. A global keyboard shortcut makes the room available without first hunting for a window.

Brightness

A continuous slider emits the same semantic value regardless of whether the bridge chooses a per-device or grouped Mesh address.

White palette

Bright, Neutral, Soft, Glow, Amber, and Candle preserve the official Oasis names and Kelvin anchors.

Expanded color

A second row provides expressive colors, followed by a full custom macOS picker for arbitrary RGB.

Management

Settings owns the machinery.

SettingPurpose
Bridge hostSelect the Mac that owns the Bluetooth Mesh connection.
Install / remove bridgeManage the app-owned background service without a separate utility.
Launch automaticallyKeep the bridge ready after login on the dedicated host.
Connection healthShow reachability and session status without pretending cached light state is authoritative.
UpdatesAutomatic checking and a manual Check for Updates action through Sparkle.
Distribution

Release builds are Developer ID signed, notarized, and delivered through a signed Sparkle appcast. The background component is bundled with the app rather than distributed as an unrelated product.
